# Bilibili CDN Filter v4.1

一个面向 Chrome / Edge 的 Manifest V3 小扩展：过滤已知容易引发 B 站视频卡顿的 PCDN 地址，并优先使用剩余的 `bilivideo.com` 播放线路。

## 功能

- 阻止以下已知 PCDN 域名：
  - `mcdn.bilivideo.cn`
  - `edge.mountaintoys.cn`
  - `szbdyd.com`
- 清除播放器返回的 `backupUrl` / `backup_url` 中的上述地址。
- 当 `baseUrl` / `base_url` 命中时，自动提升可用备选地址。
- 优先排列 `bilivideo.com` 地址。
- 在扩展弹窗显示最近命中，连续重复事件会合并计数。
- 日志不保存 URL 查询参数，最多保留 300 条。

## 安装

1. 下载并解压整个 `bilibili_cdn_filter_v4` 文件夹。
2. Chrome 打开 `chrome://extensions/`，Edge 打开 `edge://extensions/`。
3. 开启右上角“开发者模式”。
4. 点击“加载已解压的扩展程序”。
5. 选择 `bilibili_cdn_filter_v4` 文件夹。
6. 刷新已经打开的 B 站页面。

更新文件后，请在扩展管理页点击该扩展的“重新加载”，然后刷新 B 站页面。

## 使用与日志

正常播放 B 站视频即可。点击扩展图标可查看：

| 记录 | 含义 |
| --- | --- |
| `filter-loaded` | 页面过滤脚本已加载 |
| `removed` | 已从备选列表删除 PCDN 地址 |
| `promoted` | 已把命中的主地址替换为备选地址 |
| `bad-base-no-backup` | 主地址命中，但没有可用备选 |
| `DNR-block` | 请求被浏览器静态规则直接阻止 |

弹窗中的“清空”只清除本地日志，不会修改过滤规则。

## 它不会做什么

- 不修改系统代理、DNS、Hosts 或 Mihomo。
- 不重启代理核心，不切换节点，不关闭本地监听端口。
- 不读取或上传账号、Cookie、播放历史。
- 不破解会员、清晰度、地区或版权限制。
- 不保证解决所有卡顿；Wi-Fi、运营商、代理或硬件解码也可能是原因。

## 出现问题时

- **视频无法加载：** 可能本次只返回了被过滤线路。先在扩展管理页关闭本扩展并刷新页面；恢复后说明是规则命中导致，可稍后重试或切换清晰度。
- **没有日志：** 确认扩展已启用，并在安装或重新加载后刷新 B 站页面。先看是否有 `filter-loaded`。
- **只有 `filter-loaded`：** 本次播放可能没有使用列表中的域名，或者 B 站已更改接口结构。
- **仍然卡顿：** 对照关闭扩展后的表现，并检查播放器统计信息、Wi-Fi 丢包和代理线路，不要仅凭主观感觉下结论。

## 文件说明

| 文件 | 用途 |
| --- | --- |
| `manifest.json` | 扩展配置、权限与脚本声明 |
| `rules.json` | 三个域名的静态阻止规则 |
| `filter-main.js` | 清理播放器接口返回的播放地址 |
| `bridge.js` | 将页面事件安全传给扩展后台 |
| `background.js` | 统一保存、脱敏和合并日志 |
| `popup.html` / `popup.js` | 日志查看与清空界面 |

## 隐私与安全

扩展只在 `*.bilibili.com` 页面注入过滤脚本。保存的日志仅位于浏览器扩展本地存储，并去掉 URL 查询参数和片段。代码没有远程脚本、统计服务或上传逻辑。

## 已知限制

- 域名和播放器结构可能变化，需要后续维护。
- `DNR-block` 调试记录主要适用于开发者模式下加载的未打包扩展。
- 如果没有替代 CDN，过滤可能让本次播放失败；关闭扩展即可回退。
- PCDN 并非在所有地区、运营商和时间段都更慢，本项目是可回退的经验性优化。
